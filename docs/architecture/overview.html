DeepAgent Runtime Architecture

基于 Pi 官方 Extension API 的子 agent 委派系统 — 统一 dispatch、双向 RPC 通讯、会话复用

Parent 和每个 Child 之间通过 stdin/stdout JSONL 双向通讯。Parent 侧由 RpcSession 管理一个子进程的生命周期，所有子进程的运行状态由 RunRegistry 追踪，keepAlive 的空闲会话存入 SessionPool。

2. Extension 注册 — 双模式

Extension 入口 src/extension/tool.ts 根据 SUBAGENT_CHILD 环境变量分两个模式：

Parent 模式 SUBAGENT_CHILD !== "1"

注册 5 个工具 + 1 个命令：

工具用途
subagent统一 dispatch：RUN / RESUME / RELEASE
subagent_status查询运行状态 / 列出所有 runs
subagent_steer运行中注入转向指令
subagent_respond回复 child 的 pending decision
subagent_abort终止运行中的 child

命令：/doctor — 诊断，显示已发现 agents、活跃/池化数量、配置。

初始化时加载 .pi/settings.json 配置，注册 exit handler 释放所有子进程。

Child 模式 SUBAGENT_CHILD === "1"

注册 仅 1 个工具：

工具用途
contact_supervisorChild → Parent 通讯

两种类型：

  • progress — 即时返回，不阻塞，parent 无需响应
  • decision — 阻塞等待 parent 通过 subagent_respond 回复

无 config 加载、无 pool、无 monitoring 工具。返回后 child 立即退出。

3. 统一 Dispatch 流程

3.1 RUN Action（默认）

1. tasks: [{agent, task, cwd?}] 传入
2. discoverAgents(cwd, scope) 发现可用 agents
3. 校验 tasks 非空、≤ 8 个
4. Project agent 确认（scope 含 project 时弹出 UI 确认）
5. 容量检查：active + pool + tasks.length ≤ 8
6. mapWithConcurrencyLimit(tasks, 4, launchAgent)
7. 返回 run ID 列表（async）或完整结果（sync）

3.2 launchAgent（fire-and-forget）

async function launchAgent(defaultCwd, agents, agentName, task, cwd, signal, keepAlive?)
  → 解析 AgentConfig（找不到则返回错误 SingleResult）
  → new RpcSession({ cwd, env: { SUBAGENT_CHILD: "1", SUBAGENT_DEPTH: depth+1 }, ... })
  → await session.start()                           // spawn + 等待 agent_start
  → 创建 AsyncRunInfo { id: UUID, status: "running" }
  → 注册 onEvent / onUIRequest / onClose listeners
  → registerRun(runInfo)                            // 加入 activeRuns Map
  → session.prompt("Task: " + task)                 // 发送初始 JSONL
  → return { exitCode: -1, errorMessage: "Run ID: ..." }

事件处理：

事件处理
agent_endkeepAlive? → addToPool() : → 60s 后自动清理
extension_ui_request过滤 fire-and-forget 方法，其余设为 pendingDecision
进程意外关闭标记 failed/completed，5s 后清理
AbortSignal状态 → aborted，调用 session.abort()

3.3 RESUME Action

1. getFromPool(runId) 取出 keepAlive 的 session
2. 创建新 AccumulatedResult，注册临时 AsyncRunInfo
3. session.followUp("Task: " + task)
4. await session.waitForIdle(timeout) 阻塞等待
5. keepAlive? → 留在 pool : → stop + removeFromPool

3.4 RELEASE Action

session.stop()（SIGTERM → 5s → SIGKILL）+ removeFromPool(runId)

Child 进程以 pi --mode rpc --no-session 启动，Parent 通过 stdin/stdout JSONL 与之通讯。

Parent → Child

后续任务followUp(msg)RESUME 复用

Child → Parent

通过 contact_supervisor 工具：

type行为
progress 即时返回 [progress] msg，不阻塞，parent 无需响应
decision 调用 ctx.ui.input() → 发出 extension_ui_request → 阻塞等待 parent 回复

Parent 通过 subagent_status 看到 pendingDecision，用 subagent_respond 回复。超时或取消则 child 返回 { terminate: true }。

11. 顺序工作流（替代 chain）

V1 没有 chain 模式。顺序执行由 parent 自行多次调用实现，更灵活：

// Step 1: 研究
subagent({ tasks: [{agent:"worker", task:"analyze coverage"}], async: false })
// → parent 看到结果，决定下一步

// Step 2: 执行
subagent({ tasks: [{agent:"worker", task:"fix uncovered areas based on: <result>"}], async: false })
// → parent 验证，完成

优势：parent 可以根据中间结果修改下一步、跳过步骤、切换 agent、或提前中止。
